1. Ten HTML tags I reach for most

TagWhy it's useful
<div>Generic block container for grouping and layout.
<span>Generic inline container for styling a chunk of text.
<section>Groups a thematic chunk of a page (better than a bare div semantically).
<nav>Marks navigation links so assistive tech and search engines recognize the menu.
<header> / <footer>Introduces/closes a page or section with semantic meaning.
<ul>/<ol>/<li>Lists — the backbone of nav menus, cards, and any repeated items.
<img>Embeds images; the alt attribute matters for accessibility and SEO.
<a>Links — the entire point of the web.
<button>Native, accessible, keyboard-friendly interactive control (better than a styled div).
<form> / <input>Collects user input with built-in validation and semantics.

2. Header tags that matter for SEO

Researching this, the tags search engines and crawlers care about most are:

TagSEO role
<title>Shows up as the clickable headline in search results — arguably the single most important SEO tag.
<meta name="description">Powers the snippet text under the title in search results.
<h1>Should appear once per page and describe the page's main topic.
<h2>-<h6>Build a logical outline so crawlers (and readers) understand hierarchy.
<meta name="viewport">Signals mobile-friendliness, a ranking factor.
<link rel="canonical">Tells search engines the "real" URL when content is duplicated across pages.
Open Graph <meta property="og:*">Controls how the page previews when shared on social platforms.
<img alt="...">Not a header tag, but heavily weighted for image search and accessibility.

3. A 3×3 "grid" using only divs and spans (zero CSS)

No <table>, no stylesheet, no style attribute. Just the natural fact that a <div> is block-level (stacks into rows) and a <span> is inline (sits side by side). Box-drawing characters and non-breaking spaces do the rest:

┌────────┐ ┌────────┐ ┌────────┐
│  R1C1  │ │  R1C2  │ │  R1C3  │
└────────┘ └────────┘ └────────┘
┌────────┐ ┌────────┐ ┌────────┐
│  R2C1  │ │  R2C2  │ │  R2C3  │
└────────┘ └────────┘ └────────┘
┌────────┐ ┌────────┐ ┌────────┐
│  R3C1  │ │  R3C2  │ │  R3C3  │
└────────┘ └────────┘ └────────┘

Each row is its own <div> (forces a new line); each cell is a <span> joined by &nbsp; so they stay on one line. No layout CSS involved — this is pure default block/inline flow.

5. Same text, 6 font sizes, inline styles

  • The quick brown fox jumps over the lazy dog. 12px (absolute, pixels) — use for a fixed, pixel-precise caption or legal fine print that should never scale with the user's browser font setting.
  • The quick brown fox jumps over the lazy dog. 18pt (absolute, points) — borrowed from print design; useful when a layout is meant to be printed and needs to match a physical page size.
  • The quick brown fox jumps over the lazy dog. 1.5em (relative to parent) — use inside a component (like a card or button) so the text scales with that component's own font-size wherever it's reused.
  • The quick brown fox jumps over the lazy dog. 1.75rem (relative to the root <html>) — the go-to for headings site-wide, since it scales consistently with the user's base font size regardless of nesting.
  • The quick brown fox jumps over the lazy dog. 120% (relative to parent) — handy for a "slightly bigger than surrounding text" tweak, e.g. bumping up a pull-quote inside an article.
  • The quick brown fox jumps over the lazy dog. 4vw (relative to viewport width) — great for a hero banner headline that should visibly grow/shrink as the browser window is resized.

6. Four positioning options, live

The navbar at the top of this page is position: sticky — that's positioning option #1. Here are three more inside one stage (plus a bonus fixed pill in the corner of the screen):

static box (default flow)
relative box (nudged 14px down, 30px right from where it would sit)
absolute box (pinned to bottom-right of this stage)
PositionWhen I'd reach for it
stickyA navbar or table header that should scroll normally, then stick once it hits the top of the viewport.
staticThe default — almost everything, until it specifically needs to move or overlap.
relativeNudging an element slightly from its normal spot, or creating a positioning context (containing block) for an absolute child.
absolutePinning a badge, tooltip, or icon to a corner of a specific parent, e.g. a "sale" ribbon on a product card.
fixedA floating chat button or cookie banner that stays in the same spot on screen no matter how far you scroll (see the teal pill, bottom-left of the browser window).
fixed · pinned to the viewport
