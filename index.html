3. A 3×3 "grid" using only divs and spans (zero CSS)

No <table>, no stylesheet, no style attribute. A <div> is block-level so it just stacks into a new row on its own. A <span> is inline so it sits next to whatever's beside it. That's the whole trick. Box-drawing characters and non-breaking spaces do the rest:

┌────────┐ ┌────────┐ ┌────────┐
│  R1C1  │ │  R1C2  │ │  R1C3  │
└────────┘ └────────┘ └────────┘
┌────────┐ ┌────────┐ ┌────────┐
│  R2C1  │ │  R2C2  │ │  R2C3  │
└────────┘ └────────┘ └────────┘
┌────────┐ ┌────────┐ ┌────────┐
│  R3C1  │ │  R3C2  │ │  R3C3  │
└────────┘ └────────┘ └────────┘

Each row is its own <div>, which forces a new line. Each cell is a <span>, joined to its neighbors with &nbsp; so they don't wrap. No CSS layout anywhere on this one.

5. Same text, 6 font sizes, inline styles

  • The quick brown fox jumps over the lazy dog. 12px, absolute. I'd use this for fine print, like a copyright line, where I actually want it to stay tiny no matter what the reader's browser settings are.
  • The quick brown fox jumps over the lazy dog. 18pt, absolute. This is a print unit really, so I'd only pull it out if I were styling something meant to be printed, like a PDF invoice template.
  • The quick brown fox jumps over the lazy dog. 1.5em, relative to the parent. Good for something inside a reusable component, like a button, so it scales along with whatever font-size that component was given.
  • The quick brown fox jumps over the lazy dog. 1.75rem, relative to the root html element. This is my default for headings since it won't randomly change size just because it's nested three divs deep.
  • The quick brown fox jumps over the lazy dog. 120%, relative to the parent. I'd use this for something like a pull-quote that just needs to be a bit bigger than the paragraph around it, nothing dramatic.
  • The quick brown fox jumps over the lazy dog. 4vw, relative to the viewport width. This is fun for a big hero headline that you actually want to grow or shrink as you resize the browser window.

6. Four positioning options, live

The navbar up top is already position: sticky, so that's option #1 down. Here are three more in one little demo box, plus a bonus fixed pill hanging out in the corner of your actual browser window:

static box (default flow)
relative box (nudged 14px down, 30px right from where it would sit)
absolute box (pinned to bottom-right of this stage)
PositionWhen I'd actually use it
stickyNavbars, mostly. Scrolls with the page like normal, then locks to the top once it hits the edge.
staticThis is the default for everything. You only start caring about position once static stops being enough.
relativeEither a small nudge off its normal spot, or (more often, honestly) just to give an absolutely positioned child something to anchor to.
absolutePinning something to a corner of its container, like a little "sale" tag stuck on a product card.
fixedStuff that should never move no matter how far you scroll, like a chat bubble. That teal pill bottom-left is doing exactly this.
fixed · pinned to the viewport
